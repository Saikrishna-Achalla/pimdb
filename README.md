# pimdb — GPU workload analysis of TPC-H on Sirius

Profiling and analysis of TPC-H queries running on [Sirius](https://github.com/sirius-db/sirius) (a GPU SQL engine on
DuckDB + libcudf) on an RTX 5070, with all table data pinned in GPU memory so that no table data cross the PCIe bus in
the measured iterations.

## Where to start

- [`tpch_q1_analysis/analysis/results/SUMMARY_tpch_sf1.md`](tpch_q1_analysis/analysis/results/SUMMARY_tpch_sf1.md) —
  cross-query summary of Q2–Q22 at SF1, with charts and links to the 21 per-query reports.
- `tpch_q1_analysis/analysis/results/q<N>/REPORT_tpch_q<N>_sf1.md` — one report per query (Q2–Q22), next to its
  evidence files, plots, extracted metrics, SQL, Sirius logs and nsys traces.
- `tpch_q1_analysis/analysis/results/q1/` and `q1_u4/` — the earlier Q1 study and the group-by unroll (u4) experiment.
- [`tpch_q1_analysis/scripts/tpch_sf1/RUNBOOK.md`](tpch_q1_analysis/scripts/tpch_sf1/RUNBOOK.md) — how the per-query
  pipeline works and how to rerun it (`profile_query.sh <N>`, `validate_query.py <N>`, `make_summary.py`).

## Layout

| Path | Contents |
|---|---|
| `tpch_q1_analysis/scripts/` | Q1 scripts and the generic SF1 pipeline (`tpch_sf1/`) |
| `tpch_q1_analysis/analysis/results/` | per-query results and the cross-query summary |

| `sirius/` | **submodule** — upstream Sirius, pinned |
| `cudf_u4/cudf/` | **submodule** — upstream cuDF, pinned |

## Pinned dependencies

Both are git submodules: this repository stores only their URL and commit, not their contents.

| Submodule | Upstream | Commit |
|---|---|---|
| `sirius` | https://github.com/sirius-db/sirius | `f2e47849871fa8d6dc57461ee9cb8561a2af77a9` (unmodified) |
| `cudf_u4/cudf` | https://github.com/rapidsai/cudf | `2cd6c6c087c6f4ec566e20269bc8e7d87c522ed9` (tag `v26.10.02`) |

```bash
git clone --recurse-submodules git@github.com:Saikrishna-Achalla/pimdb.git
# the u4 experiment applies one patch on top of cuDF v26.10.02:
git -C cudf_u4/cudf apply ../libs/u4_unroll.patch
```

Sirius has its own submodules and a pixi environment; build it as described in its README. The Q2–Q22 results were
taken with the stock libcudf from Sirius's pixi environment, not the patched one.

## Not in this repository

- **Nsight Compute reports (`*.ncu-rep`, 6.7 GB in 33 files).** Most exceed GitHub's 100 MB file limit. They are
  regenerated by rerunning the pipeline; the metrics extracted from them (`ncu_warm_metrics.json`, breakdowns, SASS
  hotspots) are here.
- Build outputs, the built `libcudf_orig.so` / `libcudf_u4.so`, Python and pixi environments.
- TPC-H Parquet data (generated with Sirius's `tpchgen-rs` tooling under `sirius/test_datasets/`).

Absolute paths in scripts and logs refer to the machine the runs were taken on (`/home/sai/cs254_project`).
